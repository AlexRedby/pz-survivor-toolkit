Project Zomboid 42.22.2 | Сравнение отрисовки при езде на Windows

Распакуйте ZIP в новую папку. Оставьте Steam и CapFrameX запущенными, обновите моды Workshop. Оба режима используют один список модов из pack-manifest.json и отдельные сохранения в Profiles/OptimizerTrial. Если вы хотите проверить только файлы и подготовку, запустите Check-setup.cmd.

Start-optimized.cmd запускает одиночный тест с машиной. При первом запуске он скачает официальный архив xD3I (около 36 МБ), проверит его и подключит оптимизацию записи вершин четырёхугольников в буфер рендера. Если архив уже скачан, передайте его через -OptimizerZip "путь к архиву.zip". Start-control.cmd запускает тот же модпак со штатным рендером. Для Host используйте Start-optimized.cmd -Session Multiplayer и выберите PZOptimizerHost в меню Host. Клиентский оптимизатор включается только у игрока. Для последовательного сравнения закройте первый процесс перед вторым.

Если ZombieBuddy запросит разрешение на Java-моды, выберите PZToolkitJavaPatches и PZDrivingOptimizerBridge. После перезапуска игры снова откройте тот же лаунчер. Для JFR нужен JDK 25. Для записи включите HTTP API в CapFrameX. При необходимости передайте номер порта, например Start-optimized.cmd -CapFrameXPort 1337, подставив порт из настроек CapFrameX. После загрузки мира дождитесь READY FOR CAPTURE. Нажмите Ctrl+Shift+F8 в окне игры. Высокий сигнал означает начало проезда. После двух низких сигналов можно остановить машину. Дождитесь DIAGNOSTICS DONE, штатно закройте игру и дождитесь LOGS SAVED. Затем запустите Collect-results.cmd. Он принимает один Optimized и печатает путь к ZIP в папке Diagnostics. JFR и CapFrameX вручную запускать не требуется. Если для WPR в Windows нужен отдельный тест, используйте Test-WPR.cmd.

Состав испытания закреплён в current-trial-manifest.json. Лаунчер подтверждает фактически загруженные классы и моды по журналу игры. Проверка байтов и равенство данных рендера показывают, что сравниваются нужные режимы. Эффект на время кадра измеряется в игре.
