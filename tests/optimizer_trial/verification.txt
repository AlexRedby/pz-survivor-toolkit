Scope and provenance
This is the combined research candidate, rebased on remote main before packaging. It is not a main release. pack-manifest.json and build-receipt.json identify the exact committed source, common main base, component versions and file hashes. main_revision is a legacy alias for source_revision, not a claim that the candidate is published main. The optimizer's upstream source pin is recorded separately.

The selected pack has 67 gameplay Mod IDs / 62 Workshop items. Toolkit and Java Patches are bundled; Steam supplies third-party Workshop bytes, whose actual installed paths and hashes are recorded on Windows. Missing mods stop launch. Control and Optimized contain the same updated Toolkit/Java fixes; only Optimized adds the pinned external optimizer profile. Consequently this pair isolates that profile on the updated pack, not each Toolkit fix.

The default is sequential SinglePlayer on one PC: one rendered game process, separate settings/save and a ready car. The same runtime optimizations support menu Host and clients. Explicit Multiplayer uses the normal Host/Join flow and disables the SP starter. A separate extracted copy is needed when changing session type. Automatic capture expects exactly one java.exe, so a same-PC Host is not the default measurement topology. Normal installed mods/settings/saves are not overwritten. Start a new JVM before changing worlds or reconnecting: upstream animation preload supports one world session per process.

Accepted changes
- IsoLot: remove only two shared synchronized method flags at initial class definition, retaining the original parser and synchronized object pool. Exact incoming/resource hashes are required; already-loaded or unsupported classes retain their native path. The bootstrap guard cannot guarantee bytes subsequently changed by another capable Java transformer.
- Translucent-square union: bounded invocation-local identity membership avoids repeated dense-list scans, preserving order, duplicates, sorting and render callbacks. Sparse/unsupported inputs retain the native path.
- Prepare the three native outline composite shaders after world loading on the render context; native lifetime and fallback remain intact.
- Pending 2D world-item textures, including ImmersiveSnow decals, skip synchronous PNG dimension reads before the native renderer discards them. Ready textures preserve geometry and render-state commands; custom classes and non-game threads retain native getters.
- Realistic Dashboard wear overlays wait for readiness before reading dimensions. Research indicators reuse stable per-render recipe-list/player context while retaining live learning/perk/expiry checks and full drawing callbacks.
- Correct the south-edge cutaway cache value. Real edge changes still invalidate neighbouring textures; unchanged edges no longer cause the reproduced redundant invalidation.
- Menu Host removes only the authenticated client optimizer overlay from the child server classpath. Native resources, loader arguments and approval policy remain checked. MP preload starts after connection reset, joins during world loading and drains animal groups in the active client world. Buffered context flushes before verified disconnect/reset paths.
- All current-main changes at the recorded base are retained. No speculative persistent loot cache or gameplay scheduling change is delivered.

Diagnostics and remaining limits
Recorder 3.3 retains one-key JFR/CapFrameX coordination, Portable/API-port discovery, bounded download progress/timeouts, sensor/context receipts, robust collection and an owned bounded WPR session. Abrupt exits and missing sensors/ETL remain explicitly incomplete. Saved FPS caps are descriptive and do not explain below-cap stalls. Clock uncertainty, lost events and trace coverage remain separate from file integrity.

WPR selection addresses the observed old-system-binary stop error 0x80010106: a supported installed Microsoft-signed WPT/System binary is selected from standard locations and its path/hash is checked again through elevation. Test-WPR.cmd checks the same ten-second owned profile/start/stop/header/cleanup path without launching the game or capture tools. Microsoft documents the WPT >=19650 remedy at https://devblogs.microsoft.com/performance-diagnostics/wpr-start-and-stop-commands/ . Actual ETL saving on the user's Windows remains unverified until that standalone check succeeds. No global WPR cancellation is used.

PowerShell/Win32 fixtures run on macOS; they do not establish native Windows PowerShell 5.1, CapFrameX, UAC, ETW or GPU-counter behavior. The supplied Windows fog/clear recordings also differ in zoom/speed, so their FPS averages are not a causal comparison. Their stalls remain useful diagnostic evidence. The extended macOS asleep-display Display/Core cache mismatch remains unresolved; no viewport/ownership guard was relaxed. Full high-speed visual/arrival qualification, actual Windows WPR completion and a measured driving-FPS improvement remain open. The archive is ready for controlled evaluation, not a claim that all stutter is fixed.
