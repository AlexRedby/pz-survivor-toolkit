Inputs and scope
The package is a local consolidated candidate, not a published-main release. pack-manifest.json and build-receipt.json record its exact source_revision, shared main base_revision, repository versions and file hashes. main_revision is retained only as a legacy alias for source_revision. The source pin for the measured optimizer profile is recorded separately. The ordered selection remains 67 Mod IDs / 62 Workshop items. Workshop bytes are resolved and recorded on the Windows machine; they are not bundled.

Both Control and Optimized include the same updated Toolkit and Java Patches. Control has no optimizer overlay/profile arguments. These runs compare the optimizer profile on the updated pack; they do not isolate the individual Toolkit fixes. The launcher stages separate settings and saves and does not overwrite the installed game or normal profile.

Integrated runtime changes
- Realistic Dashboard wear textures wait for asset readiness before reading original dimensions, avoiding synchronous PNG-header reads. Authored size, placement, alpha and layer order remain intact.
- Research indicators reuse the stable native recipe-list reference and player index within each render. Live learning, perk changes, list size, cache expiry, bounds and player identity remain checked. The native ABBA microbenchmark found a median ratio 0.94594 for this callback, about 1.5 microseconds per 24 icons in a warmed negative-cache workload. This is a small local saving, not a driving-FPS result.
- The cutaway south-edge cache now stores the south result instead of the north result. Actual edge changes still invalidate neighbouring textures; unchanged edges no longer cause the reproduced redundant invalidation. Native full-pack SP and menu-Host/joining-client checks in the rendering track found 0/32 patched cache mismatches versus 8/32 in the native SP control.
- Current main's hidden/collapsed inventory refresh and bounded Wishlist save-path fixes are included through the recorded base. No speculative callback skipping, global loot lookup cache or gameplay scheduling change was added.

Diagnostics retained
Diagnostics format3/revision3.1 retains one-key JFR/CapFrameX coordination, Portable/API-port discovery, bounded download progress/timeouts and robust result collection. WPR uses an explicitly owned named session; the Windows10 help fallback requires a successful read-only help result and an actual instancename option. Optional WPR failure does not discard otherwise valid JFR/frame data. Conservative temporal coverage and raw loss evidence remain separate from file integrity.

The Lua observer buffers at most1800 samples of1024 bytes, with no sample/error output during gameplay. It flushes only at the bytecode-confirmed SP exit OnPostSave or OnMainMenuEnter, not ordinary saves. Collection checks trial identity, original timestamps, final count, dropped samples and coverage. Abrupt exit produces explicit partial context. Native Windows exit-event persistence remains unverified. Saved FPS limits are descriptive; a shared60 FPS cap is accepted and does not explain below-cap stalls.

Performance boundary
The supplied Windows fog/clear pair also differs in live zoom and speed, so its average32.1/36.3 FPS is not a causal optimizer comparison. Existing recordings remain useful for locating stalls. The callback census and property-surface correctness checks do not establish a driving improvement; the warmed surface allocation workload produced zero allocation in both modes, so that flag stays off. No sustained high-speed improvement or complete gameplay compatibility is claimed. The unchanged extended profile still needs its separate visibility/arrival/Host qualification before adoption into normal gameplay.
