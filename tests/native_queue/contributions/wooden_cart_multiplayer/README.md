# Wooden cart multiplayer capture intake

[Development](../../../../docs/DEVELOPMENT.md#native-scenarios) · [Native runner](../../README.md)

Source-only fixture for one owner (`client1`), one real observer (`client2`) and a native menu Host (`mp_host=true`) or the default server fixture, on B42.21. It is connected by `tools/queue_checks/adapters/carts.py`, which owns fresh preparation, launch, attachment and verification. No copied core, binary, asset or profile is included here; the manifest retains historical intake metadata. Current evidence is recorded separately in each run report. The current placement uses native floor, free-space, vehicle, room and adjacency collision checks; decorations alone are allowed.

The server creates the loaded wooden cart in its inventory authority and sends it to the owner. The owner equips the same item in both hands and calls `player:updateHandEquips()` so the native equipment pipeline reaches the observer. Global Lua `sendEquip` is SERVER-ONLY; calling it from a client prevented earlier setup. The protocol waits for both clients to observe the owner's equipped cart, then the server broadcasts a single epoch 25 seconds in the future. The analyzer compares that epoch, one owner onlineID and one cartID on server and both clients.

The scenario lasts 15 seconds: idle 0–2, walk 2–5, turn 5–8, stop 8–10, reverse with Sprint modifier held 10–12, stop 12–15. Reverse retains the native controller's gait decision; the fixture does not force remote animation variables. State logging is 10 Hz. The observer faces the owner by setting only its own local actor's native direction. Hiding UI changes local UI rendering only. The default placement finder requires an existing loaded open 13x13 footprint. With `cart_fast_motion=true`, the fresh disposable menu Host instead creates a native 31x31 floor pad at Z7 after checking its entire empty footprint and halo; both clients must observe all961 replicated floors before positioning or arming. The owner starts four tiles east of the pad centre to leave room for the Sprint braking tail. No objects are cleared. Incomplete rendered-frame coverage is insufficient evidence; the analyzer requires owner and observer frames in every phase.

`cart_variant` selects `wooden-wheelbarrow` (default), `shopping-cart` or `metal-wheelbarrow`, with authoritative exact cart/cargo IDs and actual held/rendered model checks. `cart_fast_motion=true` extends motion to26 seconds, adding native Run, Sprint-turn and stop gates inside the checked pad bounds. It seeds the fixture owner's Sprinting XP on the server and waits for the native client snapshot; it does not force Sprint animation flags. `cart_actions=true` appends six wooden pickup/setdown completion, cancellation and repeat phases through native menu callbacks. These options are frozen selection inputs.

`cart_wall_exit="front"` selects an 18-second full-load frontal brace bank on the same disposable native Host wall/pad: forward at 1s, release at 6.5s, manual reverse at 7.5s, stop at 10s, restart at 10.8s, final release at 15.5s. It requires version 1, 13-field pose payloads with flag bit 8 and actual `ToolkitCartBrace`/`Toolkit_WoodCartBrace` on owner and observer, planted rendered feet/toes at both contacts, and removal of brace after release/reverse. The existing left/right sliding-wall gates remain unchanged. Observer approach penetration stays visible in the separate footprint diagnostics; a brace result does not close that defect.

## Timing and transport baseline

Set `cart_timeline: true` explicitly in an MP resource JSON to enable the test-only trace on the owned clients and server. Omission keeps it disabled. Inventory modules are staged and register handlers only when `cart_inventory_equip` is exactly `true`; an ordinary motion bank does not start the inventory bank. With both options selected, the observer keeps its native camera character and uses native pan offsets and a close zoom to frame the owner.

The trace follows owner publication, native VariableSync parse/process/relay/write, PlayerPacket write/parse, the human `Prediction.update()` path, animation update, frozen capture IDs and consumed body/cart draws. Human remote movement does not use the animal-only `Prediction.updateLerp` path. The writer is asynchronous and bounded to 8192 queued rows and 64 MiB; missing sequences, writer errors and a missing final trailer invalidate the trace. Early TimeSync observations have a separate bounded 256-entry pending queue with explicit drop counts and connection identities.

Clients write `cart-timeline.jsonl`. A menu Host server shares the owner's cache and writes `client1/cart-timeline-server.jsonl`; the ordinary server fixture writes `server/cart-timeline-server.jsonl`. The analyzer reads the location from the frozen selection. Each native TimeSync exchange records the original client send, server reply preparation and client processing timestamps, plus the applied clock shift before/after. Its conditional offset interval is specific to that exchange. Native readiness and the 10 ms filter-correction threshold do not establish clock accuracy at arbitrary later events.

For each `GameTime.syncServerTime(t0,s,t1)` exchange, the conditional server-minus-client offset interval is `[s-t1,s-t0]`. It assumes an echoed request on the same connection/process epoch, causal ordering and constant relative clock offset/rate during the exchange. RTT includes queues and processing. Pending observations retain their original observation time and are bound later to the exact owner; startup coverage and drift between exchanges remain unknown. The probe sends no extra synchronization requests.

`firstDeliveryPublicationAgeMs` measures one observation per exact publication identity and stage. `allObservationPublicationAgeMs` also includes cached repeated values; its percentiles must not be interpreted as new-packet latency. Publication age observed at a draw is the age of the frozen variable, not the complete native image/prediction age. Native PlayerPacket has no source timestamp or unique sample sequence, so the trace does not prove an owner-time playback bridge.

Serialized cart writes and native per-connection actualBytes/resend counters are separate measurements. The latter include all traffic on that owned connection; IP/UDP header coverage is unverified. For ordinary motion, the report selects the canonical 15/26-second epoch window and uses only counter samples actually inside it, reporting uncovered edges without extrapolation. Recipient identities are not recorded, so repeated server writes and recipient fan-out are not distinguished. Inventory has its own action window and is not assigned the motion window.

`analyze-entry-contact.py` adds a read-only inventory-equip source-geometry check against explicit local game and wooden-cart assets. It requires exact outfit/mesh and consumed-draw provenance. It reports contacts and native leg/attachment measurements separately from protocol completion; source skinning is not GPU garment or all-rendered-frame certification. The game assets and capture profiles are supplied locally, while every analysis source is tracked in this repository.

## Exact native input timing experiment

With `cart_timeline: true`, native player observations retain the exact serialized/parsed body bytes, SHA256 index, packet type and per-process/actor/connection ordinals. The buffer is duplicated without moving its cursor or rewriting a packet. Submission and cancellation are recorded separately; server fan-out retains the exact source receive generation and destination. Pooled ingress and successful `Prediction.copy` into the player's persistent prediction establish local receipt/acceptance generations. Capture metadata freezes the accepted input revision when the native slot is sampled, then keeps it unchanged through both consumed draws. This revision is a current input; native root integration and skeleton phase may retain older inputs, so it is not the exclusive source of the image.

`native_packet_time.py` matches complete exact bodies and directed fixture routes. Multiple distinct source generations with identical bytes remain ambiguous; there is no nearest-time or greedy one-to-one match. Missing epochs, unknown packet type, unobserved ingress and incomplete source evidence remain qualified. Source-to-draw clock differences are point estimates, not latency bounds or a production playback bridge. Old captures remain analyzable with native-packet timing explicitly unavailable.

Set `cart_time_alignment: true` independently to enable an active clock experiment. It requires `cart_timeline: true`, `mp_host: true` and an ordinary motion bank without inventory/actions/wall banks. Only the two owned clients call the native TimeSync request API on the game thread: at most 14 attempts per client, at least two seconds apart, within the 26-second bank and a 32-second monotonic deadline. Disconnect, actor/cart/connection changes, time regression and trace shutdown stop the experiment. Ordinary `cart_timeline` remains passive, inherited environment flags cannot enable requests, and native clock-filter retries are neither suppressed nor counted as fixture attempts. No production payload or send rate changes.

Clock requests are recorded at native `TimeSyncPacket.setData`, then paired with the primitive echoed timestamp captured by `GameTime.syncServerTime`. This preserves the original reply even when a native retry reuses the cached packet during response processing. Reports distinguish fixture/native/unobserved requests, request loss, filter lag and sampled offset compatibility. `observedRequestAssociationComplete` qualifies only the observed request/reply matching. Separate `experimentCoverageComplete` requires at least two active-bank fixture attempts per client, every observed attempt prepared and replied, and no observed request/reply drops; actual elapsed spans are reported. It does not certify whole-bank sampling, clock accuracy or runtime cleanliness. A startup-only trace cannot satisfy this experiment gate. Agreement of sampled exchanges does not bound clock drift between them. Do not choose a cart-only delay or claim full source-time playback from these measurements.

The self-check composes all seven fragments, checks the real native serializer/parser and buffer identity/lifecycle helpers with `NativeTimeCheck.java`, checks scheduler limits with `ClockTimeCheck.java`, verifies native unknown-key handling and marker serialization with `ObserverAssociationCheck.java`, and retains real ZombieBuddy weaving and asynchronous trace-writer checks. It starts no game world or socket. Native Host evidence still requires a separate isolated capture through the common runner and AeroSpace policy.
