# Basement hall live fixture

The common runner owns preparation, resource admission, launch, provenance, full-log audit and cleanup. This SP-only suite requires ZombieBuddy, Toolkit Java Patches and Toolkit, plus explicit absolute executable `options.ffmpeg` and `options.ffprobe` paths. A full selected mod pack can be added without replacing the lifecycle.

`fresh` creates only `Sandbox/QueueBasementHall` in its disposable runner cache. Native character creation spawns the player on the source-verified hall landing at10707,9484,0. After initial settling the fixture captures the hall, uses native `ISWalkToTimedAction` pathfinding to descend to the basement, and returns to that same landing. The underground destination is chosen from actual loaded free floor in the basement building owning the access staircase; the random interior asset is not assumed. There is no teleport, replacement floor or synthetic staircase. Java probes check both persistent keys, native room-list/runtime-ID lookup consistency, the original building owner, actual loaded square room lookups, and identity stability during traversal. Target terrain, actor positions and native path results remain in the log. Failure retains a screenshot and saves only the disposable world for inspection. The fixture saves with the ordinary native world writer.

Export that completed run with the common world-template command, then prepare `reload` with `options.world_template` pointing to the sealed export. The same suite, ordered mods, ports and game build must match. Reload uses the native saved-game entry point and repeats the traversal. It does not convert or reset room state.

`native-control` is a fresh run with the same fixture, native walks, screenshots, completed video and save. Select a sealed JavaPatches 0.1.17 source with the common pack lock; staging rejects other versions. Its probes require both hall keys to remain `c00d3`, the old persistent lookup to point at the access hall, and the candidate key to be absent. The verifier requires the old basement-room activation and exact duplicate diagnostic, and rejects candidate key separation. Numeric IDs, original owner and loaded-room checks remain identical. It stays in `toolkit` mode so changing the Java patch does not disable the common fixture or alter the selected mod pack. Compare presented frames manually; a control pass establishes functional evidence, not visual equivalence.

One silent clip uses the existing Toolkit recorder's completed-frame hook and spans both walks. The fixture logs elapsed times for the three settled poses, waits for successful encoder completion, then the adapter checks metadata, decodes the complete video and extracts three `verification/presented-{surface,basement,returned}.png` frames just before those markers. Inspect those frames for room visibility and cutaway behavior; successful decoding does not establish visual equivalence. Raw `Core.TakeFullScreenshot` PNGs remain as comparison evidence because their current read framebuffer can omit the world. Earlier runs without presented video are historical functional evidence only. The native regression, rather than this live test, proves all-ID equivalence before/after the patch and independent flag serialization.

All three cases equip an ordinary `Base.Lantern_Propane`, fill its charge once during setup, and activate it through the native inventory action. Reload reuses an existing inventory lantern when present. Before each pose the fixture checks and logs that this item is held, active and still charged, with its native radius 15, strength 2 and non-cone light. This supplies the same real light source to candidate and control without changing time, room flags, FOV or rendering. The earlier black frames alone do not prove that missing light caused the image; inspect the new lit frames before accepting that explanation.

This source fixture is not installed into the game or a user profile. The Java helper refuses save calls outside the explicit runner cache and exact disposable world. A failed path or missing visual/saved evidence fails the suite; do not replace it with a load-only pass.
