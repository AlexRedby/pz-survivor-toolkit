# Concurrent native queue transfers

A fresh menu Host with two real clients (EN/RU), the full selected pack, original
native book producers and ordinary action durations. Compatible cases share one
world and game lifecycle. Select any nonempty ordered subset:

- `disjoint-returns`: distinct earned books return independently.
- `shared-capacity`: two books compete for one native unit of destination space;
  verify the original reservation/rejection and exact carried-item retention.
- `contested-pickup`: two clients request one physical book. Verify one owner,
  one rejected pickup and no invented earned return. The queue-enabled loser
  must retain its independent root-book tail using a fresh exact singleton
  refusal; the queue-disabled control keeps the native tail-loss behavior.
  Unknown, batch, prior-effect and unreviewed dependency shapes stay unsupported.
- `partial-accepted`: one real adjacent walking step lets the native bulk-grab
  producer group two light items. The reviewed CleanUI menu replacement remains
  active and uses the original native transfer constructors/grouping. The producer
  runs through `Operations.run`, the same shared command boundary as the real
  context-menu click. Pending actions must share that owner and remain natively
  mergeable; no queue entries or merge permissions are fabricated. After the
  real server accepts that exact two-entry request, a disposable source-gated probe moves only its second item
  to another fixture shelf through native container operations and replication.
  The original update then applies its first entry and returns false. Verify
  the server's silent Reject/removal, both clients' actual replicas and the
  requesting client's natural expiry. Preserve the paid prefix and untouched
  second item; a Lua finish or absent-byte Done query grants no singleton
  cleanup, Keep or replay authority.
- `lost-done`: last when selected. A disposable, native-source-gated probe drops
  only one exact fresh transaction's Done. Accept, Reject, native work and
  container replication remain unchanged. The server must confirm the physical
  effect before ordinary client cancellation; unknown cannot acquire Keep,
  completed-return pairing or automatic replay.

```sh
python3 tools/check_action_queue.py run "$OUT" \
  --suite queue-transfer-peers --kind mp --mode toolkit --mods selected \
  --cases disjoint-returns,shared-capacity,contested-pickup,partial-accepted,lost-done \
  --config "$CONFIG" --game "$PZ_GAME" --jdk "$PZ_JDK" --workshop "$PZ_WORKSHOP"
```

The JSON configuration requires `mp_host: true`; use a current full pack lock
and explicit candidate sources as described in the common runner guide. A
matching `--mode native` run is the queue-disabled control. Both profiles use
silent settings and disabled VOIP; common FIFO/resource/desktop ownership applies.

Before launching the partial case, staging runs the probe's headless source,
real wrapper-factory, Lua/Java argument and client/server epoch checks against
the effective staged mod layers. Unsupported CleanUI producers or entry bindings
fail preparation before a game window is created. Client readiness uses the
native client connection state; the server retains its own fully-connected flag.
Probe rejection reasons are scalar diagnostics and fail the phase promptly.

Authority snapshots count every owned ID across both player inventories and the
fixture shelves and preserve original actor items. Stop observations precede
native transaction removal. Neither advisory receipts nor the vacuous terminal
queries for an absent byte substitute for physical outcomes. Cleanup requires
both peers to drain and acknowledge phase removal. Unsafe/unknown state is not
rolled back into a fabricated successful phase.

This bank does not qualify WAN behavior, late replies after byte reuse, arbitrary
batch recovery or every queue action family. The controlled partial case qualifies
conservation and protected failure handling, not automatic batch recovery.
The signed/zero/reused-byte allocator regressions live in `NativeTransferRequestsChecks`.
