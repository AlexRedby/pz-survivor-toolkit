# Проверка FPS при езде, Project Zomboid B42.21

Распакуйте `PZDrivingBench.zip` в обычную доступную для записи папку. Нужны установленная Windows-версия игры B42.21 и запущенный Steam. Python, PowerShell 7 и права администратора не нужны.

1. Закройте игру и запустите `Start-driving.cmd`. При первом запуске пакет снимет копию графических настроек, клавиш, списка включённых модов и локальных модов из `%USERPROFILE%\Zomboid`. Workshop загружается обычным способом через Steam. Выбор модов после этого независим от основного профиля.
2. При первом запуске пройдите начальные диалоги игры, если они появятся. Дождитесь загрузки нового мира: персонаж окажется за рулём исправной заправленной машины на дороге в Muldraugh, двигатель будет запущен. Езжайте прямо, разгонитесь до скорости, при которой FPS падает, и сравните стоянку с движением. Каждый запуск создаёт новый мир; первые секунды подождите загрузку карты.
3. Для сравнения запустите `Start-vanilla.cmd`: такой же отдельный профиль с исходными настройками графики и только тестовым модом. Сравнивайте одинаковый маршрут, скорость и направление камеры. Это проверка влияния набора модов, а не точное воспроизведение сетевой нагрузки. Установленные в самой игре Java-агенты и замены игровых классов этот режим не удаляет.

Свежие миры содержат случайные объекты и зомби: сравнивайте несколько поездок. Для сравнения графических настроек в одном сохранении откройте меню через `Start-driving.cmd -Menu` и выберите нужный тестовый мир через Load.

CurrentMods берёт глобальный список из `mods/default.txt`. Набор, который включался только при подключении к чужому Host, может от него отличаться: перед выводами о модах проверьте выбор в тестовом меню через `Start-driving.cmd -Menu`. Лаунчер показывает число выбранных исходных модов; если их ноль, он выдаёт предупреждение о фактически ванильном запуске. Наличие ID в списке ещё не подтверждает загрузку: Workshop и зависимости должны быть установлены, а моды разрешены в игре.

В старом пакете первый запуск мог сбросить весь список модов, а второй включал только мод с машиной. Исправленный лаунчер сохраняет подготовленный список при первом запуске Build 42. Для восстановления уже созданного профиля закройте игру, замените `Launch.ps1` файлом из нового архива и выполните:

```bat
Start-driving.cmd -RefreshMods -Menu
```

Команда заново копирует глобальный список и локальные моды из исходного профиля, сохраняя настройки графики, клавиши, тестовые миры и настройки Host. Затем проверьте набор в меню Mods, выйдите из игры и запустите `Start-driving.cmd`. Если глобальный список пуст, нужные моды надо выбрать в этом изолированном меню; повторный импорт не восстановит набор чужого Host.

Пакет хранит профили, миры и логи в `Profiles\CurrentMods` и `Profiles\Vanilla`. Он не копирует существующие миры, аккаунты, пароли серверов и разрешения Java. Если игра запросит разрешение Java-мода, подтвердите его через обычный интерфейс игры. Нужный модам Java loader должен быть уже установлен в самой игре. Лаунчер не меняет установку игры, параметры JVM и настройки графики. Окно командной строки оставьте открытым до выхода из игры: оно удерживает блокировку профиля.

Если игра не найдена автоматически, укажите папку с `ProjectZomboid64.exe` и `projectzomboid.jar` в запросе или запустите:

```bat
Start-driving.cmd -GameDir "D:\SteamLibrary\steamapps\common\ProjectZomboid"
Start-driving.cmd -SourceProfile "D:\MyZomboid"
```

`-SourceProfile` задаёт исходный профиль при первом создании и при явном `-RefreshMods`. Для другого исходного набора распакуйте новую копию пакета; существующие профили автоматически не удаляются и не перезаписываются чужими настройками. Профиль с чужой папкой или ссылками лаунчер отклонит.

## Если разбили тестовую машину

В версии тестового мода 0.1.1 есть ручной чит для одиночного стенда:

1. Остановитесь. Можно остаться в машине либо встать рядом с ней.
2. Снимите паузу, закройте карту и щёлкните правой кнопкой по земле/объекту рядом с машиной и выберите **Driving test: repair + refuel**.
3. Машина полностью ремонтируется и заправляется. При необходимости заведите двигатель обычным способом. Мир и сама машина сохраняются.

Чит действует только на вашу зарегистрированную тестовую машину в одиночном мире `PZDrivingBench-...`. Во время движения пункт недоступен; ремонт не запускается автоматически. Пользуйтесь им между записями FPS. Он не переворачивает/не перемещает автомобиль и не заменяет сгоревший остов.

Для обновления уже распакованного набора закройте игру и замените только папку `mods\PZDrivingBench` одноимённой папкой из нового архива. Папку `Profiles` и свой выбор модов сохраните. Затем выполните `Start-driving.cmd -Menu` и загрузите прежний мир через Load. Лаунчер перенесёт обновлённый тестовый мод в существующий профиль; `-RefreshMods` для этого не нужен.

## Исходный случай: гость в Host из игрового меню

Одиночная игра помогает сравнить моды; для исходной проблемы повторите замер гостем в Host. На компьютере хоста и гостя распакуйте пакет и откройте меню командой:

```bat
Start-driving.cmd -Menu
```

На хосте откройте **Host**, выберите поставленный пресет с именем строго **PZDrivingBench** и начните новый тестовый мир. Пресет по умолчанию включает только `PZDrivingBench`; для сравнения полного набора выберите в настройках этого пресета нужные моды и Workshop, оставив тестовый мод включённым. У обоих игроков должны совпадать сборка игры, моды и их версии. При необходимости настройте подключения и разрешения через обычный интерфейс Host.

Гость подключается к этому Host из меню своего изолированного профиля. Для нового персонажа старт закреплён около `10818,10118,0`; тестовый мод подготовит машину каждому игроку. Его серверная часть работает только при имени сервера `PZDrivingBench`. Используйте только новый тестовый мир этого пресета; существующие игровые миры для этого не открывайте. Лаунчер копирует пресет только при его отсутствии и сохраняет последующие настройки Host.

После проверки сохраните `console.txt` и папку `Logs` из нужного профиля. Сообщите: одиночная игра или гость Host, полный набор или vanilla, скорость и участок дороги, FPS стоя и при движении. Новые тестовые миры и логи остаются в пакете; удалять их можно вручную после выхода из игры.

## Запись JFR во время поездки

JFR записывает работу Java-потоков и сборщика мусора. Для записи используется отдельный JDK 25 Windows x64, содержащий `bin\jcmd.exe` и `bin\jfr.exe`. Можно скачать [официальный Azul JDK 25 ZIP](https://www.azul.com/downloads/) и распаковать его. Устанавливать его системным Java или заменять игровой runtime не требуется.

1. Запустите игру обычным способом или через `Start-driving.cmd`, загрузите мир с нужными модами и сядьте в машину.
2. Запустите `Record-JFR.cmd`. Скрипт найдёт единственный процесс `ProjectZomboid64.exe`. Если JDK не найден, укажите распакованную папку JDK 25, внутри которой лежит `bin\jcmd.exe`. Можно заранее передать путь:
   ```bat
   Record-JFR.cmd -JdkDir "C:\Tools\zulu-jdk-25"
   ```
3. Нажмите Enter, вернитесь в игру, подождите 10 секунд, включите захват CapFrameX и проедьте проблемный маршрут 90 секунд.
4. Оставьте игру открытой минимум до сообщения `DONE` в окне скрипта: JFR записывается 120 секунд после задержки 10 секунд.
5. Пришлите `drive.jfr` и `capture.json` из новой подпапки `JFR\PZDrive_...` рядом со скриптом, соответствующий JSON CapFrameX и лог этой игровой сессии. Открывать JFR самостоятельно не требуется.

Скрипт подключается только к выбранному запущенному клиенту, не меняет его моды, JVM-настройки и сохранения. При нескольких клиентах требуется явный `-GamePid NUMBER`. Он не выбирает отдельный серверный процесс Host; для начала записываем именно клиент. Используйте ту же Windows-учётную запись и уровень запуска, что у игры. Подробности: [Oracle JDK 25 jcmd](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jcmd.html).

Проверены PowerShell-синтаксис, кавычки путей с пробелами/апострофом и настоящая запись отдельной JVM 25 на macOS. Запуск этого скрипта на Windows и запись самой игры агентом не проверены.

## Сборка из репозитория

```sh
python3 tools/prepare_driving_benchmark.py
```

Результат: `dist/PZDrivingBench/` и `dist/PZDrivingBench.zip`. В архив входят только лаунчер, инструкция, пресет Host и исходники тестового мода. Локальные моды, Workshop и файлы игры в архив не входят.

## Проверки и ограничения

На macOS B42.21 прошли функциональные проверки одиночного старта и настоящего Host с двумя клиентами (владелец EN, гость RU): водительские места, настоящий ключ, топливо, заряд батареи, работающие двигатели, подтверждение сервером и отсутствие дубликатов/пересечения машин. Проверки пакета и логики профилей прошли, PowerShell разобран и проверен через `pwsh` на macOS. Реальный Windows-запуск, вождение с полным набором и влияние на FPS ещё не проверены.

Общий аудит игровых логов не чистый: SP получил `needs-review`, Host — `failed` при успешных функциональных проверках из-за сообщений движка, включая font pages и неизвестные свойства `WindowShape`/`ladder*`. Эти сообщения сохранены в отчётах; тестовый сценарий их не подавляет. Это подготовленный стенд для воспроизведения, а не исправление статеров.
